# 6번 채팅·배포

이슈 #6 · 먼저 읽기: [00-start](00-start.md), [채팅 설정](../../supabase/README.md)

## 한 줄로
ABS 14기 약 30명이 익명으로 한마디를 남기는 **실시간 채팅을 켜고**, 사이트를 **인터넷 주소로 배포**한다.

## 왜 중요한가
- 배포 주소는 **제출물**이다 (과제 안내: 배포 주소 있으면 제출)
- 발표 때 30명이 동시에 한마디를 띄우는 장면이 **동료 평가(50%)** 에 가장 크게 남는다
- 발표자료·시연 영상 정리도 이 역할

## 미리 알아 둘 것
- 시작 코드가 이미 있다. 새로 짤 게 거의 없고, **설정하고 확인하는 일**이 대부분
  - `supabase/schema.sql`: 표·권한 규칙 (SQL Editor 에 붙여 넣기만)
  - `web/chat.js`: 연결·보내기·받기
  - `web/chat-test.html`: 지도 없이 채팅만 시험하는 페이지
- **Supabase** = 가입만 하면 DB와 실시간 기능을 주는 서비스. 무료로 충분
- 입장 방식: 익명 로그인 + **입장 코드** (이메일 안 받음). 코드는 단톡방으로만, 저장소에 쓰지 않는다
- `anon` 키는 공개돼도 되는 키라 `web/config.js` 에 넣고 커밋해도 된다. **`service_role` 키는 절대 안 됨**
- **GitHub Pages** = 저장소를 그대로 웹사이트로 올려 주는 기능. 우리 저장소가 공개라 무료

## 확인 방법
- `python3 -m http.server 8000` → `http://localhost:8000/web/chat-test.html`
- 일반 창 + 시크릿 창으로 두 사람인 척 → 한쪽에서 쓰면 다른 쪽에 바로 뜨는지
- 입장 코드 틀리게 넣으면 "코드가 맞지 않아요"가 뜨는지
- 3초 안에 두 번 보내면 "3초에 한 번만"이 뜨는지

## 자주 막히는 곳
- **"로그인 실패"**: Authentication 에서 Anonymous sign-ins 를 안 켬
- **메시지가 안 들어옴**: schema.sql 마지막의 실시간(publication) 부분이 실행됐는지, 입장 코드를 넣었는지
- **Pages 주소가 404**: 배포에 몇 분 걸림. 주소 끝 `/web/` 확인

## 발표 때 설명할 것
- 이메일 대신 입장 코드를 쓴 이유 (공개 저장소, 개인정보)
- 서버에서 막는 것들 (60자, 3초, 멤버만) 과 화면에서 거르는 것 (욕설·전화번호)
- 몰릴 때 말풍선 속도를 바꾸는 방식 (`pacing`)
